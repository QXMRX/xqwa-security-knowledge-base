# 第 1 节：什么是 CTF

## 本节目标

完成本节后，你应能：

1. 用自己的话解释 CTF 和 Flag。
2. 区分 Jeopardy 与 Attack-Defense 两种常见赛制。
3. 说出 Web、Crypto、Reverse、Pwn、Misc、AI Security 的基本关注点。

## 准备内容

- 一台可以访问课程资料的电脑。
- 一个用于后续学习的 GitHub 账号；没有也可以课后再注册。
- 不需要安装安全工具。

## 为什么值得学

CTF 可以理解为一组经过设计的安全谜题。题目把真实系统中会遇到的代码、协议、文件、加密数据和应用逻辑缩小到一个可授权、可复现的场景中。目标不是“攻击别人”，而是通过证据找到题目藏好的 Flag，并能解释自己为什么这么判断。

## 核心概念

### Flag

Flag 是证明你完成挑战的一段特定文本，常见形式类似 `flag{example}`。它是题目的提交凭证，不是现实系统中的密码或敏感数据。

### 两种常见赛制

| 赛制 | 特点 | 适合本课程的阶段 |
|---|---|---|
| Jeopardy | 独立题目、按类别得分 | 入门和日常训练 |
| Attack-Defense | 维护服务，同时修复与攻防 | 进阶战队训练 |

本学期以 Jeopardy 为主。它更适合在有限时间内观察、尝试和复盘。

### 六个方向先看一眼

| 方向 | 你通常会面对什么 |
|---|---|
| Web | 网页、请求、登录逻辑和服务端代码 |
| Crypto | 编码、加密、哈希和数学规律 |
| Reverse | 可执行程序、汇编和校验逻辑 |
| Pwn | C 程序、内存、控制流和防护机制 |
| Misc | 文件、流量、隐写、脚本和综合线索 |
| AI Security | 提示词、工具调用、数据边界和模型应用 |

它们不是六堵互不相通的墙。Python、Linux、网络和“把猜想变成证据”的能力，会反复出现在每一类题目中。

## 课堂主线：完成你的第一道题

在课程提供的本地题面中找到一段看起来像 Base64 的文本。尝试回答：它为什么像 Base64？解码后得到了什么？结果是否符合 Flag 格式？

建议流程：

1. 观察字符集合和末尾填充符。
2. 使用可信的本地工具或 Python 解码。
3. 核对输出是否可读、是否符合题目上下文。
4. 把你的判断写成两三句话。

## 检查点

你不需要记住所有题型。能说清“我观察到一段编码文本，所以先验证它是否可解码”，就已经完成了本节最重要的思路练习。

## 可选探索

在公开 CTF 平台中选择一题标注为入门的编码题，记录题名、类别、你尝试的工具和预计耗时。不要追求当天完成。

## 安全加餐：白帽子不是电影角色

安全研究的价值不在于“知道怎样破坏”，而在于能理解系统的薄弱处，并推动修复。白帽子测试依赖明确授权；即使一个网站看起来很简单，也不能把它当作课堂靶场。

## 课后轻任务

预计 20 分钟：用任意你信任的方式完成一次 Base64 编码和解码，并写下“编码”和“加密”有什么不同。只需 3—5 句话。

## 常见卡点

- 解码结果乱码：先确认原始文本是否被截断或含有额外字符。
- 看到陌生术语：先查术语的定义，不需要立即掌握所有细节。
- 不知道从哪里开始：优先描述你看见的字符、文件类型或网络响应，而不是猜答案。
