# CTF 课程远程授课指南

远程课堂同时使用两种材料：Reveal.js 幻灯片负责节奏、提问和演示提示，Docsify 讲义负责完整解释、命令、资源与课后复盘。教师共享幻灯片，学生在自己的窗口打开讲义；不要把讲义逐段搬上幻灯片。

## 教师开课前总检查

开课前至少提前一天完成：

```bash
uv sync --extra labs
uv run python labs/ctf-101/generate_assets.py
uv run python labs/ctf-101/verify_labs.py
uv run python scripts/check_all.py
```

然后按 [BUUCTF 优先实验题单](buuctf-labs.md) 登录平台核验当节候选题。必须实际确认附件下载和动态实例启动，不能仅凭题名仍出现在历史 Writeup 中判断可用。将验证日期、预计耗时和离线替代记录在班级内部表格。

## 95 分钟课堂节奏

| 时间 | 教师动作 | 学生产出 |
|---|---|---|
| 0—10 分钟 | 用问题或现象引入，说明授权边界 | 写下初始判断 |
| 10—30 分钟 | 讲解概念并做一次短演示 | 完成检查点回答 |
| 30—65 分钟 | 发布本地主线任务，分段提示 | 保存输入、操作和结果 |
| 65—80 分钟 | 汇总两种解法或失败路径 | 修正自己的证据链 |
| 80—95 分钟 | 安全加餐、答疑和轻任务说明 | 提交结论或卡点记录 |

## 讲义完整性标准

每节 Markdown 至少包含目标、准备内容或环境、核心概念、课堂主线、检查点、安全边界、常见卡点、轻任务、对应课件和延伸资料。实验步骤要写明：

1. 允许使用的本地、CTF 或授权环境。
2. 输入材料、预期现象和成功判据。
3. 至少一个常见失败状态及排查方向。
4. 清理或重置方式。
5. 可提交的最小证据，不以 Flag 代替过程。

## 幻灯片标准

每页只保留一个结论或一个课堂动作。代码以 8—12 行为宜；完整命令和背景解释放在讲义。演示页应写明“先观察什么”和“失败时切换到哪份离线材料”。按 `S` 打开 Reveal.js 讲者视图，使用计时器和下一页预览控制节奏。

## 关联与同步

Docsify 的每节讲义顶部会显示“打开授课幻灯片”，通用幻灯片右上角提供“详细讲义”。维护者修改课程时必须同时检查两种材料：

- 讲义新增概念后，幻灯片是否需要新增提示或演示页。
- 幻灯片调整课堂流程后，讲义步骤与预计时间是否一致。
- 标题、课次、链接和课程数量是否通过同步检查。
- 外部资源是否来自官方或可信来源，是否保留离线替代。

## 远程安全与故障预案

共享屏幕前关闭通知并移除真实 Cookie、Token、历史命令和个人路径。只演示课程提供的本地文件或授权靶场。网络不可用时切换到截图、录屏或离线附件；平台故障时记录为环境问题，不要求学生临时测试其他公网目标。

BUUCTF 归档题在课堂中失效时，最多排查 3 分钟；随后立即切换题单中的 DASCTF 同知识点题或讲义离线替代。教师共享屏幕时隐藏个人账号信息与动态实例地址，学生使用自己的账号进入题目。
