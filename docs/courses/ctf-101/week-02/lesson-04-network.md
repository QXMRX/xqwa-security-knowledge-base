# 第 4 节：网络基础与信息检索

> 通用基础 · 95 分钟 · 只观察课程环境流量

## 本节目标

- 理解 IP、端口、TCP、UDP、DNS 各自解决的问题。
- 能从一段 HTTP 交互中找到目标、方法和状态。
- 学会把模糊报错拆成可检索的关键词。

## 先抓住主线

一次网络访问不是“电脑连上网站”这么简单。它至少涉及找到主机、选择服务、建立通信和解释应用数据。分层的价值，是让我们能判断问题发生在哪一段。

## 核心概念

| 层次 | 本节关注点 |
|---|---|
| IP | 数据要到哪台主机 |
| 端口 | 主机上的哪个服务接收数据 |
| TCP/UDP | 数据以何种方式传输 |
| DNS | 人类可读名称如何映射为地址 |
| HTTP | 浏览器和 Web 服务如何表达请求与响应 |

## 课堂主线

1. 阅读一份课程提供的请求与响应记录。
2. 标出域名、路径、方法、状态码和内容类型。
3. 改变一个无害参数，比较两次响应。
4. 从一个报错中提取“工具名 + 错误核心 + 环境”三个搜索关键词。

## 检查点

看到“连接失败”时，不直接归因于网络坏了，而是能继续问：名称解析了吗、目标端口开放吗、协议是否匹配？

## 可选探索

绘制一次浏览器访问课程站点的简化时序图。

## 安全加餐：VPN、代理和加密隧道

三者经常同时出现，但作用并不完全相同。本节只解释流量路径和隐私边界，不提供绕过学校管理或访问未授权资源的方法。

## 课后轻任务

预计 20 分钟：任选一个常见 HTTP 状态码，用自己的话写出它表示什么，以及它不能证明什么。

## 常见卡点

- 把 DNS 当作网络本身：DNS 只解决名称到地址的映射。
- 只复制整段报错搜索：先删除个人路径和无关变量。
- 修改请求后无变化：比较请求是否真的发出以及响应是否来自缓存。
