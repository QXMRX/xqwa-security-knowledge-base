# 第 21 节：栈溢出原理与安全修复

> Pwn · 95 分钟 · 本地专用漏洞程序

## 本节目标

- 理解栈帧、局部缓冲区和返回状态的关系。
- 用调试器确认越界写入影响范围。
- 修复输入长度问题并完成回归验证。

## 先抓住主线

栈溢出不是“输入很长所以程序崩溃”。核心是写入超过目标对象边界，覆盖了同一内存区域中的其他状态。是否能进一步影响控制流，需要结合布局和防护证据判断。

## 核心概念

| 概念 | 关注点 |
|---|---|
| 栈帧 | 一次调用相关的临时状态 |
| 缓冲区 | 有明确容量的连续存储区域 |
| 边界检查 | 写入前验证可用空间 |
| 未定义行为 | 语言不保证结果，不能依赖一次现象概括全部 |

## 课堂主线

1. 运行教师提供的安全版本与漏洞版本。
2. 从短输入开始逐步观察边界现象。
3. 在调试器中确认被覆盖的相邻状态。
4. 使用长度限制或安全接口修复，并回归正常输入。

## 检查点

实验记录要区分“观察到覆盖”“观察到崩溃”和“证明控制流可控”三个层次。

## 可选探索

比较编译器警告和运行时检测工具能发现哪些问题。

## 安全加餐：崩溃为什么值得认真对待

崩溃可能只是可用性问题，也可能暴露更深的内存破坏。负责的处理方式是保留最小复现、评估影响并修复，而不是在生产环境继续试探。

## 课后轻任务

预计 25—35 分钟：提交漏洞成因、观察证据、修复方式和正常功能回归结果。

## 常见卡点

- 一次崩溃就宣称可利用：继续确认覆盖对象和控制流证据。
- 只缩短测试输入：真正修复应在程序中检查边界。
- 忽略返回值：安全接口也需要处理失败情况。
