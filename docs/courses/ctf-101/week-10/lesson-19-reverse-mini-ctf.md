# 第 19 节：混淆、校验与 Reverse 综合

> Reverse · 95 分钟 · 综合 Crackme

## 本节目标

- 识别简单控制流和数据变换混淆。
- 组合静态分析、动态调试与 Python 脚本。
- 完成一份带证据链的 Reverse Writeup。

## 先抓住主线

混淆的目标是增加阅读成本，不会改变程序最终必须完成计算并产生行为的事实。不要试图理解所有代码；优先找到输入、关键变换、比较和成功路径。

## 核心策略

| 现象 | 优先动作 |
|---|---|
| 伪代码很乱 | 回到调用关系和关键字符串 |
| 循环变换重复 | 提取到 Python 重现 |
| 分支很多 | 动态观察实际走过的路径 |
| 常量不直观 | 记录运算顺序，不急着命名 |

## 课堂主线

1. 选择课程 Crackme 或当期可用的 BUUCTF 入门 Reverse 题。
2. 建立输入—变换—比较—输出流程。
3. 选择一个局部算法写脚本复现。
4. 用程序运行结果验证脚本，并整理 Writeup。

## 检查点

Writeup 应说明工具为什么在该步骤有用，而不是只罗列操作截图。

## 可选探索

尝试修改一个条件分支观察程序行为；补丁仅用于本地练习，不绕过商业软件授权。

## 安全加餐：软件保护与可维护性

混淆能提高分析成本，也会增加调试和维护成本。工程选择需要在威胁模型、性能和维护之间权衡。

## 课后轻任务

预计 20—40 分钟：补全流程图或脚本注释，任选其一。

## 常见卡点

- 想理解每个函数：先追成功路径。
- 静态和动态结论冲突：缩小到一个输入和一个分支重验。
- 复制脚本后无法解释：逐行标注数据含义。
