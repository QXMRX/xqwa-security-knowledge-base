# 第 18 节：Ghidra 静态分析

> Reverse · 95 分钟 · 反编译不是恢复源码

## 实验选择

本节优先使用 [BUUCTF 题单](/courses/ctf-101/buuctf-labs.md) 中对应课次的已核验题目。教师须在课前确认题名、附件和动态实例可用；BUUCTF 归档题不可用时，切换到 DASCTF 同知识点题或本讲义的离线替代。课堂只发布题名与授权范围，不发布 Flag、账号或临时实例地址。

## 本节目标

- 导入本地程序并完成基础分析。
- 使用函数、交叉引用和控制流定位关键逻辑。
- 通过重命名和注释建立自己的程序模型。

## 先抓住主线

反编译器给出的是“符合机器行为的一种伪代码解释”，不是原作者源码。变量名、类型和结构可能不准确，必须用汇编、调用关系和运行结果交叉验证。

## 核心概念

| 功能 | 使用方式 |
|---|---|
| Functions | 从入口和调用关系寻找功能区域 |
| Strings/Xrefs | 从可见文本反查使用位置 |
| Decompiler | 快速理解高层逻辑，再回到指令确认 |
| Rename/Comment | 把分析结论写回项目，降低认知负担 |

## 课堂主线

1. 导入基础 Crackme 并运行自动分析。
2. 从成功/失败字符串查看交叉引用。
3. 重命名输入、长度检查和比较函数。
4. 将伪代码整理为流程图，并用两组输入验证。

## 实操步骤：建立可验证的 Ghidra 项目

1. 运行 `make -C labs/ctf-101/binary hello_binary`，新建非共享项目并导入生成的程序。
2. 接受默认分析器，先查看 `Window → Defined Strings`。
3. 搜索 `accepted`，通过 `References → Show References To` 跳到使用位置。
4. 在 Listing 与 Decompiler 间交叉确认调用关系，将函数重命名为 `check_input`。
5. 为参数和局部变量添加基于证据的名称，不猜测业务含义。
6. 导出一张“输入 → 比较 → 分支 → 输出”流程图，并用命令行运行程序验证。

建议记录表：

```text
地址/函数：
静态线索：
我的解释：
运行验证：
置信度：
```

反编译器恢复的类型、变量名和控制结构可能不准确。关键结论至少由指令、交叉引用或运行行为中的两项支持。项目仅导入课程文件，结束时关闭项目即可。

## 检查点

如果反编译结果与程序行为冲突，优先相信可复现行为和指令证据，而不是漂亮的伪代码。

## 可选探索

保存一份“分析前—重命名后”的截图，观察模型如何变清晰。

## 安全加餐：逆向分析的授权边界

恶意软件研究、兼容性和安全审计都有正当用途；商业软件许可、隐私和知识产权仍需遵守。本课程只分析专门提供的练习文件。

## 课后轻任务

预计 25—35 分钟：提交关键函数列表和每个函数一句话职责。

## 常见卡点

- 自动分析后信息太多：从题目可观察输出反向定位。
- 过早修改类型：先保留证据，逐步确认。
- 只看反编译窗口：遇到关键比较时回到汇编。
