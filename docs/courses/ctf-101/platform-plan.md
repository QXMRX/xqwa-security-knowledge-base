# CTF 课程题目与平台规划

## 目标

在社团服务器尚未投入使用时，课程采用“离线练习优先、授权平台替代、服务端环境后补”的方式。课程文档不硬编码临时地址、真实账号或 Flag。

## 三层环境

| 层级 | 当前实现 | 适用内容 | 后续演进 |
|---|---|---|---|
| L0 离线 | 文件、源码、PCAP、Crackme、Python 脚本 | Linux、Crypto、Reverse、Misc、部分 Pwn | 持续保留，方便无网络教学 |
| L1 公共 CTF | 教师授课前从 BUUCTF 选择仍可用的入门题 | Web 综合、方向复习 | 记录题名、方向、难度和日期，不复制平台内容 |
| L2 社团服务 | 暂不部署，只保留接口规划 | Web、Pwn、AI Security、综合赛 | 后续使用 Docker/CTFd 和独立网络环境 |

## BUUCTF 选题规则

- 只选择平台明确提供、适合教学使用的 CTF 题目。
- 授课前一周由教师确认题目仍可访问、附件完整、难度合适。
- 题单记录“题名、类别、预计时间、对应知识点、替代离线题”，不提交平台账号和 Flag。
- 若题目环境失效，立即切换离线替代，不把环境故障变成学生负担。
- 不要求学生购买会员、使用共享账号或提交个人敏感信息。

## 题目梯度

| 层级 | 预计完成时间 | 设计目标 |
|---|---:|---|
| A 主线题 | 15—30 分钟 | 单一知识点、明显反馈、课堂可完成 |
| B 组合题 | 30—60 分钟 | 组合两到三个课堂知识点 |
| C 探索题 | 60 分钟以上 | 完全自愿，服务专项兴趣 |

每节课只要求一条 A 层主线。B、C 层不参与强制周任务。

## 社团服务器后续规划

后续服务应满足：

1. 题目按课程批次隔离，默认不能访问公网或内部管理网。
2. 每名学生或小组获得独立实例，超时自动销毁。
3. Flag、凭据和日志全部使用教学专用数据。
4. Web、Pwn 与 AI 工具调用环境设置资源限制和最小权限。
5. 提供一键重置、健康检查、教师停止开关和赛后清理流程。
6. GitHub Pages 只发布静态讲义和课件，不存放动态靶场密钥。

## 教师课前检查单

- 题目授权范围和入口已确认。
- A 层主线在预计时间内可完成。
- 离线替代材料可用。
- 示例账号、Cookie、Token 均为教学专用。
- 题目停止、重置和清理方式明确。
- 课件中没有真实目标或临时密钥。
